## Shopify backend implementation

See `docs/shopify/IMPLEMENTATION.md`. Shopify defaults to disabled. The user does not have credentials or a development store yet and will provide them later. Do not request secrets in chat.

Implemented use cases under `application/service/shopify`: connect store, read/synchronize subscription, generate model, list models, get model, handle webhook, reconcile subscriptions and redact store data.

Endpoints:

- POST `/shopify/api/connection`: verify ID token, confirm installation, provision/reconnect workspace/connection/scope idempotently.
- GET `/shopify/api/subscription`: authoritative billing state and hosted pricing URL.
- POST `/shopify/api/models`: two multipart images and UUID `Idempotency-Key`; returns an asynchronous job.
- GET `/shopify/api/models`: scoped list; optional UUID `before` cursor.
- GET `/shopify/api/models/{jobId}`: scoped model/job read.
- POST `/shopify/webhooks`: raw-body HMAC verification and deduplication.

Shop scope comes only from a verified Shopify ID token, not caller-supplied workspace/store identifiers. JWT checks include HS256 signature, expiry/not-before, audience, HTTPS destination and matching issuer shop host. Online token exchange confirms shop identity using Admin API; merchant access tokens are discarded rather than persisted.

Background billing uses configured Partner API credentials. Shopify App Pricing hosted plans are used; no legacy subscription-create mutation or invented native subscription ID. Native pricing may return null legacySubscriptionId. API version is pinned to 2026-07. Partner request throttling is present. Offers map by handle and interval, fail closed if missing/ambiguous. Billing does not trust frontend redirect parameters. Periodic reconciliation replaces reliance on subscription webhooks.

Generation charges one allowance per accepted job, including jobs that later fail. Quotas are scoped independently per store. Uploads occur outside the DB transaction with cleanup on failure. Jobs and outputs cannot be read across stores. Existing direct-user/Stripe flows remain covered.

Webhooks handle app/uninstalled and mandatory customer/privacy topics. Uninstall cancels only the matching store scope. Redaction first marks the connection redacting, blocking reconnect/generation, then retries object deletion and scoped DB cleanup. Old lifecycle events cannot erase a newer installation. Customer/order data is not stored by these flows. Privacy processing deletes input objects and local records; production generated-output retention still needs provider validation.

Configuration lives under `shopify` in application.yml: enabled switch, client ID/secret, app ID/handle, Partner organization/token, version, frontend origins and job toggles/delays. Configure through environment secrets. The separate frontend must send fresh ID tokens, use stable UUID generation request IDs, redirect to hosted pricing and register backend webhook callbacks. CORS accepts only configured frontend origins. Invalid Shopify API authentication adds the Shopify session retry header.
